# Native FX packet-cadence candidate

The framework mixer emits `CE_PIXEL` after its RGB/DE/sync registers update. `arcade_video` routes nonzero FX or `forced_scandoubler` through `video_mixer`; `video_mixer` selects the scandoubler's `ce_pix_sd`. In the pinned source, ordinary scandoubling selects `ce_x2o` (two output pixels per source pixel) and HQ2x selects `ce_x4o` (four output pixels per source pixel). Against the already-qualified native /8 bridge cadence, those framework packet intervals are /4 and /2.

`exidy_native_capture.sv` generically delays `CE_PIXEL` by one master clock and captures stable post-mixer RGB, DE, HS and VS. It has no 256-pixel row restriction. Its `native_frame` output pulses on a sampled VS rising edge, and coordinate outputs are intentionally absent because this path uses no geometric reconstruction.

`exidy_native_bridge_adaptive.sv` is a separate candidate copy of the packet bridge with a two-bit cadence selector: `00` for /8 native, `01` for /4 ordinary scandoubler and `10` for /2 HQ2x. The HSC event toggles at half the selected pixel interval, preserving two HSC advances per video pixel. Change cadence only while shared asynchronous reset is held so both domains clear their packet pointers, request toggles and dividers together. Keep the original bridge unmodified until this candidate is reviewed and production integration is authorized.

Run `tools/native_adaptive/run.py` in the configured Arch WSL environment. It extracts the actual Exidy source raster and instantiates checked-in `arcade_video`, mixer, gamma, scandoubler and HQ2x sources, with source guards on the production FX and CE routing expressions. An independent accepted-packet queue checks actual settled mixer RGB/DE/HS/VS through the capture and bridge for FX0, ordinary scandoubler FX2, forced scandoubler, and HQ2x FX1. Four output-clock phase offsets (0, 333, 1000, and 1666 ps of a 2 ns period) pass. At nominal phase, each mode waits for the source and destination to transport at least two VS rising edges. Before each FX/cadence change, reset is asserted while DE is active, held across both clock domains, then mode changes while reset remains asserted. The tests check source/destination CE intervals, two HSC events per output pixel, source/capture/destination frame-edge order, and a deliberately mismatched /4 destination against the /8 source fault path. The remaining phase offsets retain the earlier bounded cadence/reset checks; they do not repeat all full-frame mode windows. This qualifies packet timing and transport, not HQ2x image mathematics, PLL clock-ratio tolerance, production modes, OSD, full game video or hardware behavior. Generated source hashes, runner result and logs remain under ignored `simulation/native_adaptive/`.
