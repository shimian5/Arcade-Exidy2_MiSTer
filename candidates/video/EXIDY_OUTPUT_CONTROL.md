# Exidy reconfigurable output PLL controller candidate

`exidy_output_control.sv` adapts Victory's GPL-3.0-or-later output controller to program the existing `pll_cfg` Avalon interface. It keeps the output clock on one reconfigurable PLL and does not use `ALTCLKCTRL` or a clock mux. Production PLL creation, fixed source-clock wiring, PLL frequency constraints, top-level integration and Quartus acceptance remain parent-owned.

The proposed source is the fixed native master divided by four. M/N/C are 128/1/32 for native and 131/1/35 for CRT; no fractional-K writes are used. The integer ratios give output rates of 1x and 131/140x relative to the master, respectively. Register packing was checked against `sys/pll_cfg/altera_pll_reconfig_core.v`: M register 4 stores low/high divide halves at bits 7:0 and 15:8, bypass at bit 16 and odd-duty at bit 17. C register 5 uses the same fields and selector bits 22:18. Thus native M/C words are `0x00004040` / `0x00001010`; CRT words are `0x00024241` / `0x00021211`. START is address 2, data 1.

The controller blanks and holds transport reset before programming. M and C writes wait for acceptance, then use guarded gaps of 256 SYS clocks; `pll_cfg` does not guarantee waitrequest busy pulses for these staging writes. START waits for acceptance, an actual busy assertion and completion, followed by lock verification and a stability guard. Two output frame boundaries are required before restoring the picture. User reset holds the output pipeline reset while preserving the selected mode. A failed clock lock re-blanks the output and restarts warmup after recovery.

Run `sim/video/run_exidy_output_control.ps1` for the isolated ModelSim fixture. It checks exact register values including bypass/odd-duty controls, pre-acceptance stalls, the M/C guard gaps, START busy/done handshake, mode switching, reset retention, lock-loss recovery and frame warmup. The runner writes a source hash audit and logs under ignored `simulation/exidy_output_control/`. This is controller simulation only; it does not verify PLL dynamic reconfiguration on FPGA hardware or the proposed top-level clock topology.
