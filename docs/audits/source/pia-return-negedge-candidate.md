# Opposite-edge PIA return-byte candidate

This is an isolated functional experiment. It does not change the production PIA wiring or timing constraints. The candidate keeps the audio-clock source register and captures the complete staged byte on the **falling edge** of `master_clk`. Its validity release also occurs on that falling edge. This is a separate proposal from the data-only opposite-edge experiment because it changes the first post-reset visibility edge.

The fixture uses the production `modules/pia/pia6821.vhd`, synthesized to Verilog by GHDL, with both PIA instances connected around the candidate Verilog block. It exercises the actual PIA PB DDR/data writes, CB2 notification, PIA9 CA1 interrupt and PA-read/CA2 handshake. It checks bytes `00`, `FF`, `A5`, `5A`, partial DDR masking (`A5 & 0F == 05`), and `C3` while CPU pause is active. It checks that the CPU sampling model sees the prior registered data bus on its PH1 enable, rather than the current combinational PA input. A reset during a pending reply checks source-reset synchronization, immediate destination masking, hidden retained data on release, and data visibility only after the falling-edge capture. The data-only negative control leaves production validity on the rising edge; it demonstrably exposes the retained `96` byte on the first rising edge after reset release, before the next falling-edge capture. This confirms why data-only edge movement violates the reset visibility invariant.

Run with `make -C sim/harness pia-return-negedge`. GHDL/Verilator passed all seven phase offsets for the 7 ns master / 22 ns audio clock pair; each phase completed seven response transactions. The bench has a 100 us watchdog and requires an explicit PASS marker per phase.

An independent root replay in fresh ignored `simulation/harness/pia_return_negedge_root/` and `pia_return_negedge_ghdl_root/` also passes all seven phases and the data-only reset negative control. This validates the bounded fixture outcome; it does not change the timing recommendation below.

The CPU/PH1 bus register is modeled at the wrapper boundary; this fixture does not instantiate the T65 CPU or execute game firmware. The pause synchronizer is production RTL, while pause stops only the modeled CPU observation; PIAs remain clocked as in the board. It is ideal RTL simulation and cannot establish fitted setup/hold timing, metastability behavior, or physical PIA/game acceptance. Treat the paired data-and-valid edge change as a candidate architecture for review, not an accepted production repair.

## Fitted clock-phase assessment

The available fitted PLL report gives the core VCO as approximately 1264.286 MHz (about 0.791 ns per VCO tick), with output 0 divider C0=28 for the 22.146 ns master clock and output 2 divider C2=88 for the 69.604 ns audio clock. Thus the output edge grids repeat in a 28:88, or 7:22, VCO-tick ratio. The production setup path report measures a 3.150 ns setup relationship for audio positive-edge launch to master positive-edge capture. This matches the edge-grid calculation: audio rising-edge residues modulo 28 are 0, 4, 8, 12, 16, 20, 24; the nearest later master rising edge is at most 4 VCO ticks away (about 3.16 ns).

Moving capture to the master falling edge adds 14 VCO ticks to the master edge grid. The corresponding residues become 14, 18, 22, 26, 2, 6, 10; the nearest later falling edge can be only 2 VCO ticks after an audio edge (about 1.58 ns). Therefore opposite-edge capture can nearly halve the minimum setup separation from roughly 3.15 ns to roughly 1.58 ns. This source/fitted-divider arithmetic makes opposite-edge capture a poor timing-repair candidate absent contrary full TimeQuest evidence. The functional sweep only checks protocol behavior; it does not establish setup improvement. No opposite-edge fitter trial is authorized or claimed here.
