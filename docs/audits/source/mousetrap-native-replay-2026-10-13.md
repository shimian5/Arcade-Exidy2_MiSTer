# Mouse Trap native callback replay — 2026-10-13

## Scope and result

This state-conditioned replay drives captured native MAME R6532 PA output callbacks into the real T80, staged Mouse Trap speech ROM, `speechRomBus`, `mousetrapVoiceIo`, MC3417 decoder, and PCM stream. It does not claim that a cold speech CPU reproduced the 38 seconds of gameplay leading to the callbacks. The source sequence and timing come from the playable native run documented in [the gameplay follow-up](mousetrap-native-gameplay-followup-2026-10-13.md).

The replay uses the three native groups `EF → F8 → FF`, `EF → F8 → FF`, and `EF → F9 → FF`; `EF` asserts PA4-controlled Z80 reset, while `F8`/`F9` release it. The measured callback intervals are passed in nanoseconds by the testbench. No production RTL or game ROM bytes were modified. The only CPU initialization is a generated, simulation-only zeroing of T80 register banks to model the MAME device constructor; the original CPU source is hashed in the run manifest.

## Native digit comparison

The comparator uses the native voice-Z80 I/O events for the MAME windows between PA release and the next reset assertion. A digit event is a write whose low-byte address has A4 low, and its data bit 0 is the serial CVSD digit. The second complete native interval contains 15,176 bits. The replay contains the same 15,176 bits in the same order; both ASCII bitstream SHA-256 digests are `b8e425bedb60b40fd32161f9458b86c50a329ba44de40cfaa58929372d717493`.

The first native interval contains 3,341 bits. The replay begins with those exact 3,341 bits but includes two additional digit writes at the reset boundary because the software CPU bus and MAME callback become visible on different clock phases. The report keeps this as a prefix match and does not call it full interval equality. The third replay segment runs for only 200 ms after the last release, so it is not compared to the much longer native capture tail.

Decoder sampling and output rendering are reported independently from digit-stream equality. The corrected ModelSim run recorded 21,633 decoder samples (21,632 nonzero), 275,030 PCM ticks (274,488 nonzero), 578,489 ROM reads, 71,627 speech-port reads, and 21,625 speech-port writes. These show live decoder/stream activity under the replayed callbacks; they are not asserted equal to native MAME PCM samples. MAME WAV evidence and its hash remain in the gameplay follow-up.

## Reproduction

Run `sim/mousetrap_native_replay/run.ps1` from the repository root with PowerShell 7. It verifies the staged ROM payload hash, compiles the actual T80 and production speech/decoder modules, and emits a private ignored result directory under `simulation/mousetrap_native_replay/`. `io.csv` preserves every CPU speech-port transaction, `samples.csv` preserves sampled MC3417 state, and `pcm.csv` preserves rendered PCM samples. The 2026-10-13 corrected run ended with ModelSim `Errors: 0` and the PASS marker in `simulation/mousetrap_native_replay/modelsim-20261013-002246-631/vsim.log`.

MAME PA source values, callback groups, busy transitions, and native voice-clock events remain in `simulation/mousetrap_voice_gameplay_postdelay_gameplay_wav/bus.csv`; neither ignored capture directory contains committed ROM bytes. No bark, meow, or chomp name is assigned based on command bytes alone.

## Extended Dog/busy tail

A separate 3,600-frame native run (`simulation/mousetrap_voice_gameplay_postdelay_busy_tail_3600/`) extends the same ordinary-input route through frame 3600. After the F9 release at 39.525189801 s, the native voice Z80 emits 220,254 digit bits before a new PA reset at 53.763357567 s (110,170 ones; ASCII-bit SHA-256 `957300632ff5ce2ecced327868e4cde3c0047a64757d8cd3a67e48c7ef89fd47`). PB0 then rises at 53.763538037 s and falls at 53.763739180 s, following the new `EF → FB → FF` PA group. This is a command-interrupted busy transition, not proof that the F9-triggered sound completed naturally.

`run_tail.ps1` replays that 14.238-second interval at the captured PA timing with reduced logging: it preserves every A4-low digit write and A5-low PB0 write, records PA edges, and emits sparse MC3417 sample/PCM checkpoints plus full counters. Its result is state-conditioned: it starts from the cold zero-bank test fixture and does not restore native warm T80 registers or RAM. The T80 enable is fixed at 1.7897725 MHz and ROM service is a one-cycle synchronous testbench response; the production wrapper uses a fractional CPU-enable accumulator and the live expansion loader's latency. These timing differences limit conclusions about exact hardware busy completion. No test result is attributed to a bark/meow/chomp phrase or to all voices completing.

The completed tail run is `simulation/mousetrap_native_replay/modelsim-20261013-003910-852/`; ModelSim passed with 6,230,215 ROM reads, 804,772 speech-port reads, 239,096 writes, 239,109 sampled decoder edges (239,108 nonzero samples), and 2,974,202 PCM ticks (2,973,656 nonzero). Native and replay intervals each contain 220,254 digit-port writes to the same address (`EF`), and all 220,254 observed clock levels at those writes are low in both captures. Comparing by event ordinal finds exactly two bit differences, at positions 1 and 2: native `0,1`, replay `1,0`. The remaining 220,252 bits match in place; this is not accepted as a shifted match or full bitstream equality. The aggregate bit hashes consequently differ. The first two write discrepancy remains unresolved and is consistent with a cold/zero-bank replay that does not restore the native warm T80 state, but that is not proven to be its cause.

`compare_tail_decoder.py` feeds every derived falling-edge D0 value, reconstructed from the replay's timed writes and sparse HDL sample timestamps, into the pinned local MAME `process_bit` C++ oracle. The local pinned source hash is `4eef48eb9589f8fd914692cd0251457495d6dc65a491326d542f20a5d8571ba4`. It checks all 23 available sparse HDL decoder rows, each sampled every 10,000 falling edges; history and Q24 state are within established tolerances and the maximum sample difference is 0.008713 PCM LSB. The edge stimulus covers 230,000 falling edges from 239,086 captured digit-port writes. This validates the replay decoder arithmetic at sampled endpoints only: it does not compare against internal native MAME decoder state, reconstruct unobserved endpoint states, or claim equality of native and replay PCM/WAV.

Reproduction of the long run uses `sim/mousetrap_native_replay/run_tail.ps1`, then `sim/mousetrap_native_replay/compare_tail.py` with the native MAME `bus.csv`, replay `io.csv`, and replay `pa.csv`. Run `sim/mousetrap_native_replay/compare_tail_decoder.py` with the completed replay directory to regenerate the pinned arithmetic comparison. These helpers write only into ignored simulation output directories; no ROM bytes are included.
