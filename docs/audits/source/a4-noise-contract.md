# A4 6840 noise clock, LFSR, gate, and level contract

This is a source comparison of the production-selected VHDL 6840 against the pinned Exidy MAME model. It does not change production RTL or claim waveform equivalence. The selected implementation is `modules/6840/berzerk_sound_fx.vhd` from `modules/6840/index.qip`; the Verilog neighbor is not selected. The comparison reference is the already-pinned MAME 0.288 source snapshot `simulation/reference_sources/exidysound.cpp`, commit `27a8d9e85b58058965907d1d8a7a92f8ed039348`.

## Clock and LFSR update

MAME defines `SH6840_CLOCK = CRYSTAL_OSC / 4` with `CRYSTAL_OSC = 3.579545 MHz`, so the Exidy 6840 E clock is nominally 894.88625 kHz (`exidysound.cpp:35–37`). The production audio board clocks `U3D_6840` from `auPH0B` with `CLK_DIV(1)` (`rtl/audio_board.v:184–197`); the surrounding comment identifies that input as the already-divided 6840 E clock. The captured timer replay's measured/expected half-period median is 0.997, consistent with the present audio PLL's approximately 0.34% faster clock. This establishes the timer pitch scale only; it does not establish noise event alignment.

MAME initializes four 32-bit LFSR words to all ones and `m_sh6840_LFSR_oldxor` to zero on device reset (`exidysound.cpp:156–164, 267–272`). For each noise clock, it computes `newxor = (LFSR_3 ^ LFSR_2) >> 31`, shifts the four words left while carrying each previous word's top bit into the next word, inserts `newxor ^ oldxor` in word 0 bit 0, and saves `oldxor = newxor` (`exidysound.cpp:106–134`).

The VHDL implements the same feedback recurrence in one 128-bit vector: `noise_xor = noise_shift_reg(127) xor noise_shift_reg(95)` and each selected edge shifts left, appends `noise_xor_r xor noise_xor`, and captures `noise_xor_r <= noise_xor` (`berzerk_sound_fx.vhd:63–65, 299–313`). With the natural word concatenation `{LFSR_3,LFSR_2,LFSR_1,LFSR_0}`, that feedback is structurally consistent with MAME. One reset difference remains: MAME explicitly resets its delayed XOR to zero, while the VHDL reset branch resets the shift register but does not assign `noise_xor_r`. The prior timer replay's simulation-only model adds an initial value for this signal; it does not validate the production reset sequence or first noise clocks.

## Noise clock source, external event, and gating

MAME updates the LFSR only when noise is needed by at least one externally-clocked timer. It computes `noisy = ((cr0 & cr1 & cr2 & 0x02) == 0)`; thus all three timer clock-select bits must indicate internal E clock for the optimization to freeze the LFSR. The noise update is also inside the timer-processing branch where channel 0 is not inhibited (`exidysound.cpp:282–340`). With `sfxctrl` bit 0 clear, MAME advances noise by the E-clock count for that audio sample. With bit 0 set, it advances noise by the number of channel-0 output rising events (`t->clocks - chan0_clocks`). The resulting noise transition count is then used as the external clock count for channels whose control bit 1 selects external clock.

The VHDL's source selection is recognizable: `ctrl_noise_and_ch1(0)=0` selects `ena_internal_clock`, while value 1 selects the detected rising edge of `ptm6840_q1` (`berzerk_sound_fx.vhd:90–95, 306–311`), matching MAME's E-clock versus channel-0-rise selection in intent. Its external timer-clock enable is formed from a detected rising edge of `noise_shift_reg(95)` (`:98–105`). Timer 3 consumes that enable through `raw3` and applies its divide-by-eight prescale when CR3 bit 0 is set (`:282–297`); MAME similarly accumulates timer-3 leftovers and divides external/internal counts by eight (`exidysound.cpp:329–340`). The earlier pitch replay covered this prescale only for timer toggles in the captured window, not noise-driven external clocks.

There are two concrete gate differences to test. First, the VHDL shifts the LFSR whenever the selected E-clock or channel-0 event occurs; it has no equivalent of MAME's `noisy` test or channel-0 inhibit guard. It therefore changes noise phase while all timers use internal clocks, and while MAME's channel-processing branch is inhibited. Second, the VHDL registers the tap edge as `noise_shift_reg_95_r`/`ena_external_clock` and the counter processes consume registered enables on later parent edges; MAME counts each output transition during `sh6840_update_noise` and supplies that count to the timers in the same stream update. The timer replay exercised internal-clock pitch, so it did not resolve this external-clock event ordering.

The tap location deserves an explicit assertion. MAME's literal post-shift output-clock test is `(m_sh6840_LFSR_2 & 0x03) == 0x01` (`exidysound.cpp:129–132`), which detects a 0-to-1 transition across the two low bits of word 2. The adjacent MAME comment calls this the “96th bit.” Under the direct concatenation mapping used by the feedback path, word 2 covers vector bits 95:64, so that low-bit pair corresponds to vector bit 64/65; the VHDL instead detects rising bit 95. The comment and literal mask therefore do not agree under that mapping. Treat this as an unresolved source-index contract until a step-by-step fixture confirms the intended word/vector ordering; do not change the RTL tap based on the comment alone.

## SFX control and volume

MAME `$3000` offset 0 stores `m_sfxctrl`; bit 0 selects E-clock versus channel-0-clocked noise, and bit 1 suppresses channel 0's audible contribution (`exidysound.cpp:306–320, 487–503`). Offsets 1–3 set timer channel volumes to `((data & 7) * (32767 / 6)) / 7` (`:500–503`). Timer 0 contributes only when its state is high, its CR7 output-enable bit is set, and the channel-0 mute bit is clear; timers 1 and 2 contribute on their high state with CR7 enabled (`:314–341`). The output is the sum of positive channel levels, then MAME normalizes it through `stream.put_int(..., 32768)` (`:343–349`).

The VHDL decodes the same four control offsets: offset 0 captures the two control bits; offsets 1–3 capture the three volume indices (`berzerk_sound_fx.vhd:164–171`). `snd1` uses timer-1 state, CR7, and the channel-1 mute bit; `snd2`/`snd3` use their timer state and CR7 (`:247–278`). Its table is linear `0,9,18,27,36,45,54,64` (`:50–54`), rather than MAME's integer values from 0 to 5461 before stream normalization. Those amplitudes enter three `jtframe_jt49_filters` channels and then the project audio mixer (`rtl/audio_board.v:288–306`). The different numeric scales cannot be declared equivalent without comparing post-filter samples at matched control settings; the existing timer replay does not measure levels.

## Focused source fixture

Use one deterministic noise-contract test with two independent checks against the same synthetic write sequence. The sequence needs no game ROM: apply `$3000` control/volume writes through `vs` and `$2800` timer-control/MSB/LSB writes through `cs`; use short periods so channel-0 rises and external timer events occur in a bounded run.

1. Initialize the reference from MAME reset state (all-one 128-bit LFSR, delayed XOR zero, all timers disabled/zero). Run a quiet interval with all three timer clock-select bits set to internal E, then switch one timer to external clock. Compare the LFSR step count/state and first external-clock events. MAME must hold LFSR state during the quiet interval; the current VHDL source advances it during that interval, so this should expose the gate difference.
2. From a separate reset, enable channel 0 with a short period, set `sfxctrl` bit 0, and make another timer external. Compare LFSR advances with channel-0 rising events, and compare the exact MAME post-shift `LFSR_2 & 3 == 1` events against the VHDL tap. This distinguishes noise-source selection from the tap-index ambiguity and the registered-enable latency.
3. Repeat a short output window with channel-0 mute bit 1 clear/set and volume indices 0, 3, and 7. Check that mute suppresses only channel 0 and record raw `snd1/2/3` values separately from filtered/mixed output. Do not infer MAME sample-level equivalence from the unfiltered 9-bit pins.

The practical fixture should run the actual production VHDL in GHDL, exposing `noise_shift_reg`, `noise_xor_r`, `ena_external_clock`, `ptm6840_q1`, and the timer outputs using VHDL external names. Use a guarded simulation copy only to initialize otherwise uninitialized simulation state; document each override and its source hash. Independently implement the MAME word shifts and output transition test in a small reference model from the pinned source, and assert every shift/tap event, not just average noise frequency. The comparison should first assert its source-derived reference sequence against a small hand-calculated prefix. A failure of the current unguarded VHDL gate or tap expectation is a recorded counterexample, not a reason to relax the reference assertion.

## Evidence and limits

The existing `local-6840-replay.md` validates timer pitch and timer-3 prescale against a Venture register-write capture. Its window begins after 31 million module cycles and explicitly does not reproduce omitted LFSR phase. It did not compare a WAV, LFSR state, external noise clock, noise phase, or post-filter amplitude. No new fixture was executed for this source-only audit. The correct next test is the reset-to-short-synthetic-sequence contract above; only after it agrees should a captured game window be used to assess phase/gating effects. Hardware audio and game acceptance remain separate.
