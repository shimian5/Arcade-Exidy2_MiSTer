# Remaining event-clock coverage review

This is a source-only review of sequential event/clock inputs not given their own SDC generated-clock model. The 07a49c5 full build was active during this review; no Quartus, STA, or build outputs were read. Source hierarchy, RTL, and the checked-in `Arcade-Exidy2.sdc` were inspected. This note does not add constraints or claim fitted coverage.

## Existing clock model boundary

The SDC calls `derive_pll_clocks` and then defines five registered pulse clocks: `BCLK`, `PH_1`, `PH_6`, `auPH0`, and `auPH0B` (`Arcade-Exidy2.sdc:70–91`). Their source equations, exact edge tuples, and discovery history are documented in [counter-clock-discovery.md](counter-clock-discovery.md) and [counter-clock-constraint-plan.md](counter-clock-constraint-plan.md). The counters and consumers remain functional RTL clocks today; the declarations do not model the event clocks below.

The SDC has a wildcard `set_clock_groups -exclusive` over PLL `divclk` collections (`Arcade-Exidy2.sdc:152`). Source inspection cannot establish which fitted clocks that pattern resolves to or which paths it cuts. Resolve the actual collections and inspect path coverage after the active flow completes before drawing conclusions about any master/audio relation. The narrow existing audio PIA handshake exceptions and first-stage reset/pause exceptions are separate (`Arcade-Exidy2.sdc:239–261`); they do not describe these event pins.

## Recommended sequence

1. Resolve post-fit SDC clock-group collections and inspect unconstrained paths/clock-pin warnings after the active full flow finishes. Confirm that the five modeled pulse clocks propagated and determine whether the `exclusive` wildcard affects intended related PLL paths.
2. Prioritize the combined `rCPU_IRQ`/`EIR` event and clear contract because it mixes raster, coin, collision, and CPU-read events and crosses into the CPU data path.
3. Separately trace CPU write strobes (`nWM*`, `nWMOL`, `nWCPL`, `WODD`, `WEVEN`) against T65 bus cycles before replacing them with parent-clock enables.
4. Build a source-bound sprite shifter and raster-boundary fixture before changing `CBLB`, `X5SRLD`, or the combinational gated BCLK inputs. Keep the `oLS166` asynchronous load/clear behavior explicit.
5. Model the legacy audio timer edges and reset/reload cases before replacing `NINC`, `TC10`, or `TNEX` with synchronous enables.

These are candidate analyses, not permission to add broad clock declarations or false paths. Event pins should remain normally timed wherever the implementation can be expressed as a genuine clocked enable; asynchronous controls need a demonstrated capture/reset contract before any narrow exception is considered.

## Post-fit coverage evidence (07a49c5)

The read-only `check_timing` report completed against full fit `07a49c5` after that flow finished. It reports 3264 `no_clock`, 118 `multiple_clock`, 96 latch, and 1 loop issues. The 3264 count is not a count of Exidy core defects: the no-clock table has about 170 entries under the Exidy hierarchy, about 1856 `h2f_gp~FF_*` HPS entries, and about 1238 other system/blackbox entries. The Exidy subset includes the event source nets listed above, event-clocked raster/sprite state, and AUDIO_RAM input registers; each group still needs its own endpoint and source review. The report also has 32 multi-clock entries for the four 8-bit sprite shifters, plus video/HDMI interface endpoints. No blanket event-clock assignment follows from these counts.

The seven Exidy nodes explicitly reported as feeding clock pins without clock assignments are `PH_6B`, `T65:M6502|AD[0]`, `hscnt[5]`, `audio_reset|rst_sync`, `U3AB_counter[0]`, `U1AB_counter[0]`, and `NINC`. `rst_sync` is being detected as a clock because it drives sequential clock pins in the audio design; that does not make reset a functional clock domain. The generated divider pulse clocks are present in `report_clocks`; `check_timing`'s `generated_clock=0` count reports no generated-clock check issues, not absence of generated clocks.

The root SDC and `sys_top.sdc` each report the same `-exclusive` group command. Post-fit resolution of its groups yields: emu core PLL group contains the 22.146 ns output 0 and 69.604 ns output 2; HDMI PLL group contains one 6.732 ns clock; `pll_audio` contains one 40.682 ns clock; and `spi_sck`, `hdmi_sck`, `h2f_user0_clk`, `FPGA_CLK1_50`, `FPGA_CLK2_50`, and `FPGA_CLK3_50` each resolve to one clock. Since the emu PLL output 0 and output 2 clocks are in the same group, the exclusive inter-group rule does not cut paths between them. The PIA audio-stage-to-master-data path is still analyzed and fails setup; its worst slack is -0.439 ns. This establishes group membership, not the reach of every exception. See generated `simulation/coverage-07a49c5/clock-group-members.txt`, `check-timing.rpt`, and `exceptions.rpt` for the complete output.

The first `get_register_info -clock` probe returned empty or edge objects and did not provide usable register clock associations, so the final report relies on Quartus 17's successful `check_timing` output for actual no-clock endpoints. `report_exceptions` reports exception reach; `report_sdc` lists clock-group expressions, while the diagnostic separately expands those expressions through `get_clocks` to enumerate group members.
