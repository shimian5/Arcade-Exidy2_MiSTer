# Generated-clock and event-signal inventory

## Scope and evidence

This is a source review of the completed full-flow Quartus run `simulation/quartus-full-2026-10-07.log` (Warning 332060 inventory), not a new build. The log emits the same clock warnings twice (at approximately lines 2072–2096 and 2343–2365, corresponding to report passes); they are one set of findings, not independent failures. The run reports 11 promoted/automatic clocks, but also identifies multiple RTL nodes as clocks with no clock assignment. Source citations below use repository-relative paths and line numbers. Relevant implementation is in `rtl/Exidy2.v`, `rtl/audio_board.v`, `rtl/reset_sync.v`; SDC evidence is in `Arcade-Exidy2.sdc`.

The main core PLL output is nominally 45.153061 MHz in its generated-IP source (the full-flow SDC applies a 48/5 relation to FPGA_CLK2_50 at `Arcade-Exidy2.sdc:59`). The Exidy divider comments at `rtl/Exidy2.v:86-92` describe older/contradictory frequencies and should not be used as the authority. The counters below are driven by `master_clock` or `audio_clk`; rates are exact integer event-rate ratios to those parent clocks, not measured fitted-clock rates.

## Clock mux and constraint observations

The full-flow fitter protects muxes, including T65 `PCAdder`/`Mux290`/`Mux178` and `cDET_sel` (`log:1120-1131`). These are reported as clock multiplexers, but source context identifies arithmetic/data selection and collision selection, not evidence of clock switching. Preserve them as data muxes; investigate only if a consumer’s clock pin is actually downstream. Do not treat the protection message alone as a request for clock constraints.

`Arcade-Exidy2.sdc:55-61` contains hand-authored generated-clock constraints for PLL internals. The run says the line 61 generated-clock target and `-source` are empty (`log:1963-1965`; repeated `2234-2236`), so that hand constraint is ignored. The log then reports a derived clock at the `general[2]` output (`:2061`), but do not infer that this repairs line 61. The existing `set_false_path` for `rst_meta` is narrowly justified by the two-flop reset synchronizer (`Arcade-Exidy2.sdc:271-274`). The SDC also declares asynchronous/exclusive clock groups (`:180`); groups do not substitute for modeling the internal pulse/event clocks above.

## Recommended ordering

1. Consolidate PH_1/BCLK/PH_6/PH_6B consumers into their true parent clock domains using explicit enables, beginning with simple raster counters and serial shifters. This removes generated event clocks and gives TimeQuest ordinary same-domain paths.
2. For any retained divided domain (notably audio submodules that require a clock pin), derive and constrain it from the actual PLL output and confirm the fitted relationship and edge/pulse waveform. Avoid relying on stale comments or a 50% duty assumption for one-cycle enables.
3. Replace data-derived clocks (`hscnt[5]`, CPU `AD[0]`, `NINC`, `TC10`/`TNEX`, counter bits) with edge-detected or decoded enables in the chosen parent domain. Handle asynchronous external/reset controls separately and document synchronizer intent.
4. Re-run the full Quartus flow and inspect the post-fit clock report, unconstrained-path report, and the exact former consumers. Do not use broad false paths to silence inferred-clock warnings; only a synchronizer first stage or a proven asynchronous interface should receive a narrowly scoped exception.

This inventory does not claim the recommended RTL restructuring is behaviorally equivalent or that the current image is unusable. It records source and report evidence to guide a later targeted timing fix. No RTL, constraints, build outputs, or tests were changed/run for this task.
