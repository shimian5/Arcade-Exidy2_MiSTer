# Expansion loader RTL prototype

This isolated RTL prototype exercises the accepted transport contract without changing or instantiating the production core. `sim/expansion_loader/exidy_expansion_loader.sv` accepts the loader's begin/write/end events, validates the extended marker and literal 16-byte descriptor, forwards index-0 writes live, and stores question/CVSD streams in independent memories. It holds the external reset gate until the declared profile streams are complete and rejects noncontiguous addresses, wrong lengths, unarmed streams, and malformed descriptor version/magic fields. The design allocates the full 192 KiB question store and 16 KiB CVSD store; no scaled memory estimate is used.

The fixture has synthetic test data only. It checks Mouse Trap profile `$03` with marker `$90` and 16 KiB CVSD, then FAX profile `$01` with marker `$b0` and 192 KiB questions. Question bytes vary by bank and byte offset; independent literals assert bank starts/ends (offsets `0`, `8192`, `180223`, `180224`, and `196607`). It checks bank 24's provisional zero fill. CVSD values vary in 4 KiB quadrants. Transfer scenarios cover successful completion, index 2 after completion, live legacy index-0 writes, legacy index-0 then index-1 recovery, address holes, an empty/aborted marker, nested begin, malformed descriptor version/profile/mask/base-length/reserved byte, an unarmed late payload, and a full question stream after a duplicate-base fault. That last case confirms later payload completion cannot clear the prior fault or restore readiness. An unknown index after completed CVSD playback revokes its independent readiness gate and the fixture checks it after the two-flop synchronization delay. The prototype does not rely on clearing physical base storage.

The main-read fixture reproduces the observed Exidy2 timing shape: a `PH_1` pulse every 64 master clocks, a registered memory read output, a registered `CPU_databus_in`, and T65 sampling of the previous registered input. Stable-address reads pass. A negative case changes to a distinct bank near the sampling deadline and observes the stale byte at that T65 sample, then the expected byte at the next enable. This demonstrates a timing constraint for integration; it does not prove that the production memory primitive meets it. The separate CVSD-clock read is modeled with two-flop readiness synchronization, but physical CDC and reset/download quarantine remain unverified.

Run from Windows PowerShell with WSL Arch and Verilator installed:

```powershell
wsl.exe -d archlinux -- bash -lc 'cd /mnt/c/MiSTerDev/Arcade-Exidy2_MiSTer && LC_ALL=C bash tools/expansion_loader/run_sim.sh'
```

This remains a protocol and timing model, not top-level integration or a fit result. It has no production MiSTer HPS CDC, does not gate actual T65 reset, and has not been synthesized in Quartus. The CVSD read clock, readiness deassertion during overwrite, RAM inference/port behavior, and the installed MiSTer binary's acceptance of the proposed MRA order need separate validation. FAX profile flag `$30` is provisional. FAX PROM wiring/storage remains open, and banks 24–31 are deterministic zero fill with parity unproven; bank 24 behavior must not be described as MAME-equivalent. The known FAX/FAX2 expansion layout and MRA transport prerequisites remain in [the storage contract](../rom-expansion/expansion-storage-contract.md) and [transport model report](../expansion-transport/transport-model.md).
