# FAX / FAX 2 candidate integration route

This checkpoint records the production loader/core binding and the remaining FAX acceptance gaps. It does not establish complete-game or hardware acceptance.

## Candidate path

1. MRA index 1 carries the extended-download marker plus the proposed exact profile byte: `F4` for FAX (`74` after removing the marker) and `F8` for FAX 2 (`78`). Index 7 carries descriptor profile 1 or 2, mask `03`, index-0 base length `0x014A40`, question length `0x030000`, and zero CVSD length.
2. Index 0 contains the MAME program ROMs, sound CPU ROMs, graphics ROM and declared PROMs. Its candidate byte count is 84,544 (`0x14A40`). Index 5 carries 24 consecutive 8 KiB question banks (196,608 bytes). These two candidate files are [FAX](../../candidates/mra/FAX%20(question%20expansion%20candidate).mra) and [FAX 2](../../candidates/mra/FAX%202%20(question%20expansion%20candidate).mra).
3. The production expansion loader binds descriptor profile 1 to normalized PCB `0x74` and profile 2 to `0x78`, while retaining speech profile 3 ↔ PCB `0x10`. It recognizes only extension marker bytes `0x90`, `0xF4`, and `0xF8`; legacy `0xB0` and `0xD0` do not arm the extension path. The production `exidySpeechLoader` routes raw index 5 only after a valid profile 1/2 descriptor, exposes question readiness after the complete image is accepted, and preserves the existing speech interface.
4. Production top-level normalization strips the marker bit from `0xF4`/`0xF8`, and QIP includes `fax_controls.v`, `fax_profile_controls.v`, and `fax_question_window.v`. The core exposes FAX profile/readiness-qualified P1/P2 inputs, the diagnostic startup option, PH_1-qualified question-bank writes, and question reads ahead of ordinary memory fallback. FAX expands work RAM from legacy 1 KiB to 2 KiB with CPU and host address bit 10 selected only for validated FAX profiles. `candidates/fax/` remains an unbound comparison copy.

## ROM and map evidence

Pinned MAME configures a 32-entry bank table rooted at main-CPU offset `0x10000`; each entry is 8 KiB. The ROM region is only `0x40000` bytes, so entries 0–23 are in-region and entries 24–31 point beyond it. FAX has 22 loaded banks and two explicitly unpopulated `NO_DUMP` sockets (banks 22–23); its candidate stream fills those two absent sockets with zeros to preserve the loader's exact 192 KiB contract. FAX 2 has 24 loaded banks. The declared `fxl-12b` PROM is marked “loaded, but not hooked up” by MAME and has no consumer in the pinned source, so it does not affect the candidate bank map.

MAME masks bank writes with `data & 0x1f`. A passive 3,600-frame FAX 2 capture selected bank 24 once, then selected bank 0 before any question-window read; FAX selected banks only 0–22 in the same bounded capture. Banks 25–31 were not observed. The isolated loader returns deterministic zero for selectors 24–31, but that is a quarantine policy and not proven MAME/hardware parity. Complete play must record whether those values are read and resolve the out-of-region behavior.

The question read path needs two sequential stages: the expansion RAM's registered output, then the existing master-clock `CPU_databus_in` register. `faxQuestionWindow` supplies the bank and read/address request plus priority data; the production integration must retain that final register stage. The isolated fixture covers bank-latch decode, first/last window addresses, non-FAX fallback and data priority. The helper fixture covers exact profiles, readiness loss during reload, each answer bit, starts and normal startup bit 2.

## Remaining acceptance

The current helper default makes IN3 bit 2 low because both pinned FAX games only reached their reference question flow after a diagnostic override. MAME declares this bit unused and active low/high at idle; its physical strap meaning remains unknown. Keep the candidate default explicit and retain the reference caveat until board evidence exists. P2 face-button mapping through `joystick_1[7:4]` and the HPS mapping also need hardware confirmation.

The profile/input and bank/window fixtures are `sim/fax_controls/tb_fax_profile_controls.sv` and `sim/fax_controls/tb_fax_question_window.sv`, driven by [run.sh](../../tools/fax_bind/run.sh). Verilator 5.052 passes both: 17 profile/input/readiness checks and 10 bank/window/read-priority/read-latency checks. The actual T65 CPU fixture [tb_fax_t65.sv](../../sim/fax_cpu/tb_fax_t65.sv) executes synthetic 6502 bytecode through the source-extracted production read mux and checks separate `$0000`/`$0400` RAM, question-bank reads, P1/P2 and startup input, plus legacy fallthrough; its ModelSim runner passes at 4,506 cycles.

The [MRA image builder](../../tools/fax_bind/build_mra_images.py) expands candidate XML using staged archives into ignored `simulation/fax_bind/mra_images/` streams. It checks XML order `[1,7,0,5,2]`, descriptor/profile/length pairs, archive CRCs, and each full question-image SHA-256. The candidate loader fixture [tb_fax_mra_loader.sv](../../candidates/fax/tb_fax_mra_loader.sv), driven by [run_mra_loader.sh](../../tools/fax_bind/run_mra_loader.sh), covers loader-level bank and latency behavior. The production-wrapper fixture [tb_fax_wrapper_transport.sv](../../sim/speech_loader/tb_fax_wrapper_transport.sv), driven by [run_production_wrapper_transport.sh](../../tools/fax_bind/run_production_wrapper_transport.sh), uses the extracted HPS source file/GPIO ACK path and both actual MRA XML streams. For both sets it checks all base tuples, every loaded question byte, all 48 first/last bank reads, zero reads for banks 24–31, wrong profile/marker rejection, B0 legacy and ignored-index-5 recovery, and a synthetic profile-3 speech path after reset. The existing actual-ROM Mouse Trap wrapper regression also passes with the added question ports idle. The production wrapper fixture does not exercise the CPU graphics/core join, board startup straps, or Quartus integration. No private ROM bytes or simulation output are committed.
