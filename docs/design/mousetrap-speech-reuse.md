# Mouse Trap speech implementation reuse audit

## Finding

This is a feasible, bounded extension of the existing audio system, not a reason to call Mouse Trap speech impossible. The repository already contains a reusable Z80 core, while a reusable CVSD decoder exists in the adjacent `wolf-unit` checkout. The speech ROM transport and isolated read interface are also modeled and tested in this project. What is missing is the production integration that connects those pieces to the existing 6502/RIOT behavior and to the audio mix.

This is source analysis only. No source was copied, no production RTL/QIP/MRA changed, and no Quartus build was run. The target MAME evidence is commit `27a8d9e85b58058965907d1d8a7a92f8ed039348`; the local preserved MAME copy available for inspection is from a different pin (`d4024db0e8e3824d937e3d9a165119a8eb4829a2`). Its Mouse Trap implementation agrees on the contracts below, but use the target-pin links when making future changes.

## Pinned Mouse Trap board contract

The source map is in pinned MAME [`exidysound.cpp`](https://github.com/mamedev/mame/blob/27a8d9e85b58058965907d1d8a7a92f8ed039348/src/mame/shared/exidysound.cpp#L633-L715), and the four sound-CPU ROM declarations/order are in [`exidy.cpp`](https://github.com/mamedev/mame/blob/27a8d9e85b58058965907d1d8a7a92f8ed039348/src/mame/exidy/exidy.cpp#L2033-L2040). The preserved local cross-check is `C:\MiSTerDev\_publish\Arcade-Victory_MiSTer\docs\reference\exidysound.cpp` and `.h`; it records a separate MAME source pin in that package README.

| Block | MAME behavior | Integration consequence |
|---|---|---|
| Speech CPU clock | `CVSD_Z80_CLOCK = CRYSTAL_OSC / 2`, where `CRYSTAL_OSC = 3.579545 MHz`; nominal Z80 rate is 1.7897725 MHz. | The main audio CPU is nominally 3.579545/4 = 0.89488625 MHz. At the current STA audio-clock model of 69.604 ns, an audio-domain Z80 enabled every 8 audio-clock cycles would run at about 1.7958 MHz (roughly 0.34% above MAME nominal). Confirm the actual fitted PLL rate and choose a divider/clock source deliberately. Do not use auPH0 (every 16) for this Z80. |
| Z80 program map | Global address mask `0x3fff`; ROM at `$0000-$3fff`; no RAM is mapped in the speech CPU program space. The four 4-KiB ROMs fill the 16-KiB window. | Connect `mem_rd` to the isolated index-6 read port for all 16-bit addresses after 14-bit masking. Writes can be ignored/open bus as the MAME program map is ROM-only. Address is already 14-bit at the candidate store interface. |
| ROM ordering | MAME region order is `mta_2a.2a`, `mta_3a.3a`, `mta_4a.4a`, `mta_1a.1a`; each is 0x1000 bytes. | Do not alphabetically sort by socket label. The existing expansion contract specifies the 16-KiB index-6 payload in MAME region-address order. |
| I/O map | Global I/O mask `0xff`; every port `$00-$ff` is handled by the same read/write methods and decoded by address bits. | Decode low address bits directly; there are aliases across the full byte I/O space. Preserve the selected-bit behavior below rather than assigning four isolated registers. |
| Voice writes | For `OUT (n),A`, if I/O address bit 4 is clear, D0 drives the MC3417 digit input. If address bit 5 is clear, D0 also drives RIOT PB0. These tests are independent, so one write may do both. | Implement a single write decoder preserving both side effects. The CVSD serial bit is Z80 D0, sampled on the MAME decoder's clock edge. PB0 feeds the existing audio RIOT input path. |
| Voice reads/status | Start with `$ff`. If I/O address A7 is clear, low nibble becomes `bitswap(cvsd_data,3,0,2,1)`. If A6 is clear, bit 7 becomes the CVSD clock state. | `cvsd_data` is the byte last written by the audio RIOT PA callback. The low-nibble mapping is output bits 3:0 = input bits 3,0,2,1. Read bit 7 reports the CVSD clock; untouched bits retain the `$ff` defaults. |
| RIOT control/reset | MAME routes the 6502 RIOT PA-write callback to `cvsd_data_w`. That saves the full byte and releases the Z80 reset when bit 4 is one; bit 4 zero asserts Z80 reset. | Gate the Z80 with this firmware-controlled line in addition to global image/reset readiness. The reset line must not be inferred from Mouse Trap's index-1 `0x10` byte alone: Venture shares that legacy hardware byte. Presence/validity of the CVSD descriptor/index-6 image is the unambiguous speech-profile selector. |
| CVSD clock | MAME toggles `m_cvsd_clk` from a periodic timer at `CVSD_CLOCK * 2`, then calls `clock_w` on every toggle. `CVSD_CLOCK = 1 / (0.693 * (2.4 kΩ + 2*20 kΩ) * 2200 pF)`, about 15.5 kHz. Thus there are about 30.96k toggle callbacks/s and about 15.48k rising sample edges/s. | This is independent of the Z80 instruction rate. Feed a clock enable to the candidate CVSD core at the decoder's required sampling edges, and expose the modeled clock state for Z80 status reads. Validate timer edge polarity and bit/data setup against MAME traces or hardware. |
| Decoder/output | MAME uses `MC3417`, then two cascaded op-amp low-pass filters (each MFB stage uses 10 kΩ, 3.9 kΩ, 18 kΩ, 20 nF, 2.2 nF); the CVSD route gain is 0.3086 to offset the filters' gain. | The adjacent `hc55564` is algorithmically related but uses a different named device/model and has no MAME's analog filters. A usable speech waveform needs a deliberate decoder comparison and filter/gain model, not merely ticking a CVSD module. |

## Existing project path and gaps

The main-board-to-audio-board command path already exists: main CPU `$5200-$520f` writes PIA 9B; PIA 9B's PB output reaches PIA 8B's PA input, with CA/CB handshake lines carrying notification. The audio T65 6502 runs with `auPH0` as a clock enable, and the RIOT is selected for `$0800-$0fff` through `io08_0F`. Audio RAM is already mapped with the Mouse Trap 128-byte mirror needed for its firmware polling behavior.

The current RIOT instance leaves `pa_out` and `pb_out` unconnected (`rtl/audio_board.v`); there is no Z80 instance, speech I/O decode, `cvsd_data` status/reset register, or CVSD output in the production audio path. The MRA omits the four sound ROM parts. `rtl/rom_loader.sv` currently has no production index-6 route or speech store consumer. `eprom_7` is not instantiated for this use, and its legacy 14-bit write address would wrap a payload appended after the existing index-0 image. The current audio mix has no CVSD input. Isolated adapter model ports and passing transport tests establish a storage/transport candidate only; they do not establish the CPU bus or production integration.

One behavior requires attention in the first integration design: RIOT PA output direction/DDR and the current core's simplified `R6532` port semantics must match MAME's `pa_wr_callback` behavior. The audio RIOT is a local RTL implementation with explicit `pa_in`/`pa_out` ports in `modules/riot/R6532.vhd`, but `audio_board.v` currently does not wire them. Likewise PB0 status must feed `pb_in` with correct DDR masking, and Z80 status I/O must reflect MAME's returned byte for every address-bit combination. Do not wire raw dual-clock byte buses as CDC controls.

## Bounded implementation units

1. **Pin the CPU/audio contract.** Add an isolated bus-level test for T80 with a small combinational ROM, then a one-cycle synchronous ROM that asserts active-low `wait_n` until data is available. Verify a read is held through the T-state-2 sample, data is neither stale nor skipped, and `mem_rd`/`io_rd` are distinguished. Confirm `intreq=0`, reset polarity, and exact CPU enable ratio.
2. **Connect RIOT-to-CVSD control only.** Unit-test RIOT PA DDR/data writes and MAME bit-4 reset polarity, PB0 write behavior, CVSD status bit wiring, and independent decoder reset. Keep the Z80 disabled in this step; compare against the pinned MAME handler truth table.
3. **Add ROM fetch and I/O semantics.** Connect index-6 valid store to Z80 `mem_rd` through the tested wait-state adapter. Implement full masked I/O map for data bit writes and status reads. Replay captured MAME Z80 bus transactions if available; otherwise use exhaustive address-bit/D0 checks and a small synthetic ROM. Verify the actual MAME ROM stream is exactly 16 KiB in region order without committing bytes.
4. **Validate decoder and audio path.** Select or adapt the CVSD decoder under its license, implement nominal 15.5-kHz clock behavior and the two filter stages/gain model, then compare bitstream/sample output against MAME/device traces. Add CVSD output into the existing mono audio mix with bounded level tests. Game-level speech audibility and reset/reload still require hardware or emulator acceptance.
5. **Close integration gates.** Add an explicit Mouse Trap speech profile based on the extended descriptor/index-6 validity, preserve Venture behavior despite their shared legacy index-1 byte, hold Z80 reset until the exact index-6 image is validated, synchronize reset release in each clock domain, and run full Quartus fit/timing plus voice-ROM reload/pause tests. None of these acceptance claims follow from the current isolated adapter model.

Remaining hardware assumptions include the exact board CVSD analog transfer response, MC3417 versus HC55564 algorithm/clock polarity parity, the audio RIOT PA/PB electrical DDR defaults at reset, the CVSD timer's first phase, and the physical meaning of the HPS descriptor readiness during pause/reset. Keep those as open validation items rather than silently choosing values.
